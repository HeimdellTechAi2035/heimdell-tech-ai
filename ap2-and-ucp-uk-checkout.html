How AP2 and UCP Work Together for UK Shops

A checkout journey, not a readiness checker

Quick answer: UCP is how an agent finds a shop’s products and starts a checkout. AP2 is how the payment is authorised, using a signed mandate tied to that checkout. A UK shop needs clean product data and plain-text policies before either protocol helps. This page is not a readiness checker. Implementation is a custom quote.

Two jobs in one checkout

Shop owners hear the two acronyms together and wonder whether they must buy both. They do different jobs.

On 11 January 2026 Google announced the Universal Commerce Protocol as an open standard for agentic commerce. Google said UCP was co-developed with industry leaders including Shopify, and that it is built to work with existing protocols including Agent2Agent (A2A), the Agent Payments Protocol (AP2) and the Model Context Protocol (MCP). The announcement is on Google’s ads and commerce blog.

The UCP specification says a business publishes a profile at /.well-known/ucp. That profile is a JSON document. It states a protocol version, the services the business offers, optional capabilities, and payment handlers. A platform, such as a shopping agent, reads the profile, and the two sides agree which capabilities apply to that session. Catalogue browsing and checkout live on this side of the line.

The AP2 specification (v0.2) is narrower. It says AP2 secures a payment an agent performs. It is a security feature inside a commerce protocol. Catalogues, checkout updates and the messages between the parties are outside AP2. The same page says AP2 is designed to be compatible with UCP. Payment authorisation lives on this side of the line.

A short way to remember it: UCP is the conversation about the goods. AP2 is the signed permission to pay for a particular checkout. Our four-way comparison puts all the standards on one page. This guide stays on the checkout only. The separate explainers are UCP readiness and what AP2 is.

A plain journey, with no shop names

The steps below follow the public specifications. They are not a claim that a named UK shop, or every UK shop, can do this today. No customer is invented here.

  1. Browse. The agent fetches the business profile from /.well-known/ucp and reads the product data the shop has made available: name, price, currency, availability and description. If those facts are only in an image, the agent cannot quote them reliably.
  2. Basket and checkout. UCP capabilities are named by the business. Google’s published profile example includes a shopping checkout capability, with fulfillment as an extension of checkout. The agent assembles a checkout: the items, quantities and the delivery or collection choice the shop actually offers. The merchant provides a merchant-signed checkout document. AP2 calls this a checkout JWT.
  3. Checkout mandate. The Checkout Mandate is how the merchant gets cryptographic proof that the shopping agent is allowed to purchase that checkout. The mandate is bound to the merchant-signed checkout using a hash, so a later change to the basket does not silently keep the old permission.
  4. Payment mandate. The Payment Mandate is separate. It is proof, for the credential provider, the network and the merchant’s payment processor, that the agent may pay for that checkout. It is bound to the same checkout by a hash of the checkout JWT. The closed payment mandate includes the payee, the amount (an ISO 4217 currency code and an integer in minor units, so pence for sterling) and the payment instrument. A date of execution is optional. If it is absent, the specification treats the payment as immediate.
  5. Confirmation. Once the merchant accepts or rejects the checkout mandate, it returns a checkout receipt. Once the payment side accepts or rejects the payment mandate, a signed payment receipt is returned. Those receipts are the specification’s record that a decision was made, not a promise that the goods have already been delivered.

AP2 describes two modes. In the human-present, or direct, mode the person sees the closed checkout and approves it and the payment. In the human-not-present, or autonomous, mode the person has approved constraints on what checkout an agent may complete. A shop should decide which mode it is willing to accept, and say so in the customer journey, before it turns anything on.

On 28 April 2026 the FIDO Alliance said it would develop specifications for agent-initiated commerce, drawing on Google’s AP2 contribution, inside its Payments Technical Working Group. The public AP2 documents remain the place to read the mandate model. Standards work after a contribution can still change the detail, which is why we re-read the current specification before building.

What a UK shop needs before either protocol helps

A profile and a mandate cannot repair a vague catalogue. Before either protocol is useful, a shop needs facts an agent can read as text.

  • Identity. The trading name, a contact method and a postal address a customer can save. Distance-selling rules expect this information to be available before an order. See the consumer-law guide for the official links. This page is not legal advice.
  • Products. A name, a description that matches the goods, a price in a stated currency, and whether the item is available. Identifiers such as a SKU help an agent look up the same product twice without guessing.
  • Delivery and collection. Cost, method and how long goods take. If you offer several speeds, say which one is the standard option. An agent that invents a next-day promise is using a gap in your text.
  • Returns and cancellation. Written in sentences, not only inside a photograph of a policy. Include when a customer can cancel, which items are excluded, and how to send goods back.
  • A profile that matches the shop. The UCP profile should advertise only capabilities the shop can actually complete. A checkout endpoint that fails, or a price in the profile that disagrees with the product page, is worse than no profile.

The same preparation is described, from a small-business point of view, in agentic commerce for UK small businesses. Platform differences for Shopify and WooCommerce are in UCP for UK Shopify and WooCommerce shops.

Proof of what the customer authorised

The AP2 specification says the checkout mandate and the payment mandate can be used as evidence when there is a dispute. That is the point of binding both of them to one checkout document the merchant signed. The merchant can show which items, which amount and which payee were inside the authorised checkout. The customer, or their agent, can show the same thing.

A mandate is not a substitute for consumer rights. If the buyer is a consumer and the contract is a distance contract, cancellation and refund rules can still apply. A signed permission to pay £40 for a jumper does not, by itself, remove a right to cancel that the law gives. How refunds and proof sit together is set out in When an AI agent buys: UK consumer law and proof of mandate. We do not publish dispute rates, win rates or chargeback statistics, because we do not have official figures of our own to cite.

Clear product data matters here for a practical reason. If the checkout text said “blue, size M” and the mandate is bound to that text, there is a record. If the only description was a photograph, there is an argument instead of a record.

Frequently asked questions

Do I need both AP2 and UCP?

You need UCP, or an equivalent commerce connection, if an agent is to read your catalogue and start a checkout. You need AP2 if that agent is also to be authorised to pay with a signed mandate. A shop that only wants agents to read products can start with catalogue data and UCP. A shop that wants agents to pay needs a payment authorisation as well. Many shops need neither yet.

Does AP2 and UCP replace my Shopify or WooCommerce checkout?

No. UCP is a way for an agent to discover what a shop supports and to carry out commerce actions the shop advertises. Your existing checkout can remain the way a person pays in a browser. Platform support also differs, and it changes, so check the current Shopify or WooCommerce documentation before you assume an agent can check out.

Is this live for every UK shop yet?

No. The specifications are public, and some platforms publish a UCP profile, but that does not mean every UK shop can take an agent payment today. Payment providers, the shop platform and the country of the checkout all matter. We will say plainly if it is too soon for your shop.
